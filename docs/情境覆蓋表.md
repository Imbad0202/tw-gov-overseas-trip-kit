# 國外差旅情境覆蓋表

核對日期：2026-09-06。這份表區分「工具算得出來」和「案件適用已經認定」，後者仍由機關辦理。計算規則對齊 114.05.13 修正、115.01.01 生效的版本；日支數額須自行查適用出差日期的官方表。

**目前定位：單一人員、單趟出差的文件與美元經費規劃。** 多人可各建一份資料；沒有團費分攤、預支沖銷、訂票、簽核、核銷送件或保險理賠系統。出國報告與旅費報支的適用對象、期限也不同。

## 行前、途中、返國後

| 情境 | 支援程度 | 填法／下一步 | 驗證依據 |
|---|---|---|---|
| 建立資料、驗證、產檔 | 自動 | `tripkit init / validate / render`；不需寫 Python | `tests/test_cli.py` 完整使用流程 |
| 一般短期出差、自理膳宿 | 自動試算 | 每日 `per_diem_base`、`host_provided: none` | `test_per_diem_calc.py` |
| 同趟多國、多城市、不同季節費率 | 填值後自動 | 每日一筆；填當日適用基準額與 `rate_source`，工具不查表、不猜城市 | 混合情境範例第 3 日 |
| 同日跨多城市 | 填值後自動 | 依當日留宿地選一個基準額；同日不可拆多筆日支 | 重複日期回歸測試 |
| 未列城市／國家 | 人工查表 | 查該國「其他」；未列國家比照距離最近國家「其他」，記錄依據 | [數額表官方附件](https://ws.dgbas.gov.tw/001/Upload/461/relfile/10693/235615/25-%E4%B8%AD%E5%A4%AE%E6%94%BF%E5%BA%9C%E5%90%84%E6%A9%9F%E9%97%9C%E6%B4%BE%E8%B5%B4%E5%9C%8B%E5%A4%96%E5%90%84%E5%9C%B0%E5%8D%80%E5%87%BA%E5%B7%AE%E4%BA%BA%E5%93%A1%E7%94%9F%E6%B4%BB%E8%B2%BB%E6%97%A5%E6%94%AF%E6%95%B8%E9%A1%8D%E8%A1%A8.pdf)附註 |
| 主辦供膳宿、僅供膳、僅供宿 | 自動試算 | `board_and_lodging / board_only / lodging_only` | 四種供應模式單元測試 |
| 主辦只供部分餐、附早餐 | 填值後自動 | 使用有供膳的模式，`meals_not_provided` 列未供的餐；不可重複餐別 | 混合情境第 2 日；基本範例午／晚餐 |
| 供膳宿另給現金津貼 | 自動試算有限情形 | `cash_allowance_usd` 扣零用補足，最低 0；高額或有指定用途津貼另洽主計 | 零用補足與超額測試 |
| 僅現金津貼、未供膳宿 | 不自動認定 | 現模型無對應規則，拒絕默默算全額；人工核定後用獨立人工項目 | 非支援組合拒絕測試 |
| 機上／交通工具歇夜 | 填值後自動 | 一般供宿不供膳用 `lodging_only`；仍須依實際供餐核對，勿當返國日 | 混合情境第 1 日 |
| 返國當日 | 自動試算 | `is_return_day: true`，單趟限最後一筆；併供膳宿、津貼等另覆核 | 返國日單元測試 |
| 因私提前出國、中途休假、私人延留 | 可明示排除 | 保留日期，`reimbursable: false` + `exclusion_reason`；因私提前另填 `approved_start_date`，私人交通費勿另加入 | 混合情境第 4 日 |
| 未核准延返 | 期間已填時自動排除 | 必填 `approved_days` 才有期間限制；未填會提醒，不會自動排除 | 混合情境第 5 日；缺日邊界測試 |
| 患病、天候、班機延誤等核准延返 | 核定後自動 | 填 `approved_extension: true`，`note` 記證明與核准依據 | 混合情境第 6、7 日 |
| 提前結束公務返國 | 填值後自動 | 依實際日期縮短 trip 與逐日資料，末日標返國；不用補滿原核准天數 | 日期起訖檢核 |
| 長期同地駐留／豁免 | 有限模型，須覆核 | `day_index_same_place` / `reduction_exempt`；既有模型採 30/90 日界線，**不自動判曆月**，不從城市名推斷日序 | 30/31/90/91 日與豁免測試 |
| 行前議程、住宿、聯絡、交通銜接 | 文件支援 | `itinerary / lodging / emergency_contacts / notes`；可空陣列；下車、轉乘、回程寫在 note | HTML 與空區塊驗證測試 |
| 直飛、轉機、過夜、行李未知、票價未知 | 比較支援 | 獨立候選 JSON → `tripkit flights`；來源、查詢日期、優缺點需自己查填 | `test_flight_rank.py`、CLI 五文件測試 |
| 換日線、跨多日、首場公務隔兩天以上 | 部分支援 | 航班排序僅有時刻與 +1 布林，**不能準確計算完整時間軸**；逐日議程寫完整日期，人工核對報支日數 | 既有航班多日限制測試；CLI 提醒 |
| 出國報告已有素材與正文 | 文件支援 | `summary` + `report_content`；另可填 `report_title / report_date` | DOCX 內容及 CLI 測試 |
| 只有基本資料、尚未出發 | 文件支援 | 先產手冊／審核表／經費表；report 須有摘要與本文，骨架另用 `--allow-incomplete-report` | 缺摘要、缺本文測試 |
| 補正後重新產檔 | 支援 | 改 JSON 後重新產檔；換輸出資料夾或明示 `--force` | 覆寫保護測試 |

## 須人工決定或另用制度

| 情境 | 本工具如何承接 | 不會自動做的事 |
|---|---|---|
| 機票、船票、市區／城際公共交通 | `manual_items` 記已核定美元金額與單據依據 | 艙等資格、外籍航空申請、必經順路票價上限、憑證審核 |
| 廉航附加費、行李、改退票、行程取消 | 核定後逐項填人工金額；退款可負值並註明原列項目 | 可報性、保險理賠、重複補助判定；取消行程無生活費可只填人工項目 |
| 覈實住宿／主辦指定旅館／旅行社包辦 | 人工計算**相對於已列日支的淨調整**，於 note 列出組成 | 不得在全額日支之外再疊加整筆住宿；工具不自動防止重複計列 |
| 護照、簽證、保險、報名、註冊、刷卡手續費 | `manual_items` + 憑證／核准備註 | 適用條件、限額、保單承保範圍 |
| 禮品交際、計程車、租車、團費 | 人工填核定額；多人各檔避免同筆重複 | 人數／職務限額、團長專案核准、跨人員分攤 |
| 新臺幣／外幣、信用卡結算、匯差 | 此表只收 **USD**；由承辦換成美元規劃值並註明幣別、匯率、日期、來源 | 不可把新臺幣直接加進 `amount_usd`；最終臺幣核銷、預支沖銷另表處理 |
| 多來源補助、部分自費 | 人工調整淨額、記出資與扣抵依據 | 補助歸戶、避免跨機關重複請領的審核 |
| 大陸、香港、澳門 | 可記行程；費用須帶入專用日支表 | 不套用一般國外數額表；第 22 點另有表格 |
| 外派常駐、進修研究實習補助、非一般公務身分 | 可利用報告／手冊格式，費用另行確認制度 | 不因報告類別可填「進修」就認定適用本計算器 |
| 受刑或停免職等限期返國 | 人工處理 | 第 18 點個案通知、期間與核定 |
| 跨年、跨數額表生效日 | 每日帶適用數額、註明來源 | **僅數額變更**可逐日填；若計算規則也變更，換 `per_diem_base` 不足以處理，須分版本另算 |
| 簽證、入境登錄、護照效期、疫苗、安全警示 | 查官方即時資料後寫入手冊 notes | 不提供固定免簽天數、醫療判斷或即時警示服務 |
| 行前申請、機關客製表、多人共同報告、附件與照片 | 另依機關流程／Word 編修 | 不讀機關範本、不合併多人資料、不上傳報告、不代簽核 |

表中手動報支方向請見[個案指引](延返與個案指引.md)，適用條件以[主計總處現行要點](https://law.dgbas.gov.tw/LawContent.aspx?id=FL017584)及機關核定為準。

## 可跑的混合情境

```bash
python -m tripkit render --finance examples/04-mixed-scenarios.trip-finance.json --out output/mixed
```

七日合成日支依序為 `30、13、200、0、0、100、30` 美元，合計 373；人工機票 420、保險 40、退款 -10，規劃總額為 **823 美元**。這些基準額是用來驗證程式的整數，並非任何城市的官方費率。

相關測試：`tests/test_finance_scenarios.py`。所有計算先保留精度，總計後才進位；Excel 保留原基準額、排除原因與人工備註，方便覆核。

## 已知計算界線

長駐「一個月／三個月」與既有 30/90 日模型不完全等義；長駐與返國／供餐津貼併用、僅收津貼、特殊住宿等組合沒有完成個案法規判定。不要把通過測試當作這些個案已確認。必要時改以經機關確認的人工淨額規劃，並保留計算底稿。

`grand_total_usd` 延續本工具「日支＋人工項目總額進位」的美元規劃算法；它不是新臺幣核銷數額，亦不代替日支進位與其他費用各自適用規定的正式結報。
